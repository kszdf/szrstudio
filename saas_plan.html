一、目标架构图（多租户 SaaS）

说明：绿色=云端按量 API（你的 key，需计量限额）；橙色=数字人视频算力（最贵，决定架构）；紫色=成品存储；红色=租户数据与权限（隔离是合规底线）。

核心判断：「授权他人用、但不能改代码」在 SaaS 下天然成立——别人只有账号和界面，碰不到服务器代码。RBAC 角色（超级管理员 / 租户管理员 / 操作员）即可精细控权。你现在这套 Python+HTML 几乎能直接搬，改造成本最低。

运营变动成本（两档都要付） 云端 API 按调用计费，归到「每租户用量」里计量限额：

  • CosyVoice 配音：约 ¥0.01–0.03 / 分钟音频（按字符/时长）
  • DeepSeek 文本：极便宜，约 ¥0.001 / 千 token，可忽略
  • Tavily 联网搜索：免费 1000 次/月，超出 $0.004/次
  • 这些是你的 key 产生的费用，多租户必须做「用量计量 + 配额/计费」，否则被白嫖。

三、分阶段改造清单

阶段 1 · 先能「自己→别人」用（1–2 周，低成本）

  1. 鉴权层：登录/注册 + JWT/Session；RBAC 三角色（超级管理员 / 租户管理员 / 操作员）。
  2. 多租户隔离：项目归属 tenant_id；每个租户独立目录/库；A 客户看不到 B 客户的稿子。
  3. 部署上线：买域名 + 免费 SSL；CPU 云服务器；用 Nginx 反代 rewrite_studio.py；Docker 编排 HEYGEM。
  4. key 管理：CosyVoice/DeepSeek/Tavily 的 key 留在服务端，前端永不暴露；按租户配额。

阶段 2 · 计费与合规（2–4 周）

  1. 用量计量：记录每租户 TTS 字符数 / 视频分钟数 / API 调用 → 限额或阶梯计费。
  2. 合规：用户协议 + 隐私政策；上传脚本/音频加密存储；明确经营资质（财税内容+收费）。
  3. 运维：访问日志、错误监控、进程自动重启、每日备份（项目+成品）。

阶段 3 · 轻量入口与扩量（按需）

  1. 微信小程序：只做手机端轻操作（选题、看成品、下载、留资钩子），重活仍走后端。
  2. 视频算力上云：当且仅当多人高频出片、本地顶不住时，再上 GPU 云服务器（方案B）。
  3. APP：暂无刚需，不优先；等出现离线/推送/摄像头需求再评估。
落地建议：从阶段 1 + 方案 A 起步，月成本控制在 ¥540 左右 就能让客户通过域名登录使用，且「碰不到代码」。视频先在本地出、或手动转交，等跑通收费模型、有稳定租户后再上 GPU 云（方案 B）。切忌一上来就买 GPU 服务器——那是最大的成本坑。
