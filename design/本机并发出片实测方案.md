# 本机并发出片方案（基于实测硬件）

> 文档目的：上一版《并发出片方案》里"本地多开 2–4 个 HEYGEM 灶台"是对大显存显卡的泛泛估计，**未结合你这台机器的真实配置**。本文用 `nvidia-smi` 实测结果重新给出可落地的方案。

---

## 一、先回答你的核心疑问："多开"是要配多台电脑吗？

**不是多台电脑。**

"多开 HEYGEM 灶台"的意思是：在**同一台电脑**上，同时启动 **2–4 个 HEYGEM 的 Docker 容器**，每个容器只占你显卡（GPU）显存的**一部分**，像一个大厨房里并排放几个灶台，共用同一块显卡的计算力。

- 能不能多开、**能开几个**，取决于你这块显卡的**显存（VRAM）**有多大，跟"电脑数量"无关。
- 如果一台电脑的显卡显存不够，要真多人同时出片，要么**换一块更大的显卡**（还是一台电脑），要么**去云上租用显卡算力**（等于租用远程电脑的显卡，按用时算钱）。都不是让你买一堆普通电脑。

## 二、本机实测配置（2026-07-30）

| 项目 | 实测值 | 说明 |
|---|---|---|
| 显卡型号 | NVIDIA GeForce RTX 5060 笔记本显卡 | 消费级笔记本 GPU |
| 显存总量 | **8151 MiB（约 8 GB）** | 这是决定并发数的硬上限 |
| 当前占用 | 3525 MiB（约 3.5 GB） | 只跑 1 个 HEYGEM、且处于待机状态 |
| 空闲显存 | 4286 MiB（约 4.3 GB） | 渲染时 HEYGEM 占用会更高 |
| 容器显存限制 | 无（占满整卡） | 默认会吃光 8GB |
| 其他容器 | heygem-tts / heygem-tts-old 均已退出 | 不占 GPU |

**关键判断：**
- 1 个 HEYGEM 待机就吃 3.5GB，**真正渲染时占用更高（通常 4–6GB+）**。
- 你这块卡总共只有 8GB，所以：
  - **跑 1 路**：稳，留有余量。
  - **硬跑 2 路**：两路各分 ~4GB，几乎把 8GB 吃满，渲染高峰期极易触发 **OOM（内存撑爆，对应之前反复出现的 `137` 崩溃）**——反而会更不稳定。
  - **跑 3–4 路**：物理上不可能。

**结论：你这台 8GB 笔记本显卡，本地多开这条路基本走不通，现实是"1 路稳、2 路勉强且危险"。** 之前说的"2–4 路"是按 24GB 以上大显卡估的，对你这台机器不适用，特此纠正。

## 三、三条路对比（哪条适合你）

### 路线 A：异步队列（本机立刻能做，0 元）✅ 推荐现阶段
不增加任何显卡，而是改变"提交方式"：

- 用户点"出片"不再原地干等，而是**进入队列，显示"前面还有 N 位 / 预计 X 分钟"，炒好了自动通知**。
- 后台仍是 1 个 HEYGEM 串行渲染，但**多个人的任务排队不互相阻塞、不报错、不卡死**。
- 体验从"点了没反应/报错"变成"已接单，好了叫我"——**彻底解决你担心的"体验感极差"**。

| 项 | 内容 |
|---|---|
| 现金成本 | 0 元（纯软件改动） |
| 效果 | 多人可同时提交、互不干扰；单人等待时长不变 |
| 适用阶段 | 内部自用 / 早期小范围试用 / 卖给少量客户 |
| 局限 | 单条出片速度没变快，人多时排队变长 |

### 路线 B1：换大显卡（一次性投入，本地真并发）
买一块大显存显卡装进一台台式机：

- RTX 4090（24GB）：本地可稳跑 **2–3 路**
- RTX 5090（32GB）：本地可稳跑 **3–4 路**

| 项 | 内容 |
|---|---|
| 现金成本 | 一次性 ¥15,000–25,000（显卡 + 一台能插显卡的台式主机；你现在是笔记本，需另配主机） |
| 计费方式 | 一次性买断，之后无月费 |
| 效果 | 本地真多人同时出片，速度快、不排队 |
| 局限 | 并发上限被这块卡锁死；机器坏了全停；扩不了太多 |

### 路线 B2：云 GPU 弹性扩容（SaaS 真解，按用量付费）✅ 推荐增长期
队列积压、本地灶台全忙时，**自动去云上开 GPU 机器扛活，闲了自动关掉**：

- 平台=本地 1 路（保底）+ 云上 N 路（按需）
- 客户越多，云上自动开越多"灶台"，你不用堆显卡
- 按 **GPU 使用时长** 计费，空闲不花钱

| 项 | 内容 |
|---|---|
| 现金成本 | 云 GPU 约 **¥1.5–8 / 小时**（24GB 级别）；一条 1 分钟视频渲染约 2–5 分钟 → 单条算力 **¥0.1–0.7** |
| 计费方式 | 按 GPU 小时（或 Serverless 按秒）计费；不用不花钱 |
| 效果 | 并发无上限、随业务弹性伸缩；客户感知"随时能出" |
| 局限 | 需联网；单条有云机器启动预热（几秒~几十秒）；需做任务调度层 |

## 四、推荐落地路径（结合你这台机器）

```
现阶段（本机 8GB）→ 路线 A：异步队列
   ├─ 多人同时提交 ✅
   ├─ 显示排队位 + 预计时长 + 完成通知 ✅
   └─ 0 元、几天可上线，先把体验和"能接多人的单"解决

增长期（开始卖给财税同行）→ 路线 B2：云 GPU 弹性
   ├─ 本地 1 路保底，云上按忙闲自动扩缩
   ├─ 算力成本 ¥0.1–0.7/条，被订阅费轻松覆盖
   └─ 客户无感知"你家显卡够不够"，永远有灶台

（可选）本地也要快 → 路线 B1：换大显卡
   └─ 仅当你想本地就扛住 2–3 路、且不愿依赖云时再买
```

**一句话建议：**
你这台 8GB 笔记本**别硬上多开**——先用**路线 A（异步队列，0 元）**把"多人提交不卡死"解决，这是现阶段最划算的一步；等真开始对外卖、客户量起来，再上**路线 B2（云 GPU 弹性）**，并发和扩容都不是问题。换大显卡（B1）是可选的后手，不是必经路。
