### 0.2 我们的差异化定位（不要硬刚，要错位）

我们的底盘是**本地 HEYGEM 数字人 + CosyVoice 真人克隆音 + 滚动字幕卡**，本质是"**自有品牌数字人 + 零按分钟成本 + 数据完全私有**"。与头部比，我们不拼"预制形象数量/实时直播"，而是拼：

1. **真人克隆为核心**（客户最关心：我的脸我的声，不被平台绑架）
2. **无限次克隆/重克隆/删除**（头部平台克隆名额受限、重训收费 → 我们本地零边际成本，这是真优势）
3. **多账号自有矩阵分发**（头部锁平台生态，我们走自托管分发）
4. **一站式脚本→成片**（我们已有选题→二创→脚本→出片链路，对标 HeyGen Video Agent）

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                    主控制台 Web (app.html)                 │
│  管理后台(租户/权限/日志/设备)  │  创作台(选题/二创/脚本/出片) │
└───────────────┬───────────────────────┬───────────────────┘
                │  HTTP/JSON             │
┌───────────────▼───────────────────────▼───────────────────┐
│              rewrite_studio.py (统一网关 + 路由)            │
│  ├─ _auth_gate (租户token + 设备指纹校验)                  │
│  ├─ 权限中间件 (每次请求按 tenant_permissions 校验)         │
│  ├─ 计量中间件 (usage_records 累加 + 阈值触发)             │
│  └─ 业务路由 (选题/二创/脚本/出片/租户/设备/权限/日志)     │
└───────────────┬───────────────────────┬───────────────────┘
                │                        │
┌───────────────▼──────────┐  ┌──────────▼──────────────────┐
│   studio.db (SQLite)      │  │  文件系统 (按租户隔离)        │
│  租户/用户/设备/权限/日志/ │  │  data/<tenant_slug>/         │
│  分类/模特注册表/计量/计费 │  │   {audio,video,pkg,models}/  │
└──────────────────────────┘  └──────────────────────────────┘
```

**关键设计原则**
- 所有写操作经 `tenant_id` 行级隔离；旧单租户数据迁为 `default` 租户，不丢历史。
- 权限/计费在**请求中间件**实时生效，不依赖重新登录（满足"权限变更实时生效"）。
- 大文件（音视频）不入 DB，仍走文件系统按 `tenant_slug` 隔离。

## 2. 设备管理模块

### 2.1 数据模型
```sql
CREATE TABLE devices (
  id TEXT PRIMARY KEY,            -- device_id (UUID)
  tenant_id TEXT NOT NULL,
  name TEXT,                      -- 用户自定义设备名 "张总办公室主机"
  fingerprint TEXT NOT NULL,      -- 机器指纹 (主板UUID+磁盘SN+用户名 hash)
  is_primary INTEGER DEFAULT 0,   -- 是否当前主控制台
  status TEXT DEFAULT 'offline',  -- online / offline
  bound_at INTEGER,
  last_seen INTEGER,
  verified INTEGER DEFAULT 0      -- 新设备是否通过验证
);
```

### 2.2 核心流程
- **绑定**：首启自动生成 `device_id` + `fingerprint` 并存本地；调用 `/api/device/bind` 上报，自动成为该租户的 `is_primary=1` 主控制台。
- **解绑**：`/api/device/unbind`（需主设备确认或管理员令牌）。
- **切换设备**：新电脑安装后上报 fingerprint → 若未登记 → 返回 `need_verify` → 用户在前一台已绑设备/管理员后台**批准**或输入**一次性验证码** → 验证通过后绑定，原主设备可降级为从设备（"当前电脑及更换后的电脑均可作为主控制台"→ 支持主备切换，不互斥）。
- **状态识别**：`/api/device/heartbeat` 每 30s 上报 → 更新 `last_seen`；超过 90s 未心跳标记 `offline`。
- **自动维护**：后台定时任务扫描 `last_seen` 维护在线/离线；绑定关系存 devices 表。

### 2.3 身份验证
- 控制台访问 = `tenant_token`(租户级) + `device_token`(设备级) 双因子。
- 未登记设备访问受限接口 → 401 + `need_verify`，仅放行验证相关接口。

## 3. 多租户管理模块

### 3.1 数据模型
```sql
CREATE TABLE tenants (
  id TEXT PRIMARY KEY,
  slug TEXT UNIQUE,               -- 用于文件路径隔离
  name TEXT,
  plan TEXT,                      -- free / pro / enterprise
  status TEXT,                    -- active / suspended / expired
  expire_at INTEGER,
  created_at INTEGER
);
CREATE TABLE tenant_config (
  tenant_id TEXT PRIMARY KEY,
  category_schema TEXT,           -- JSON: 自定义分类体系
  brand_kit TEXT,                 -- JSON: Logo/主色/字体
  default_model TEXT,
  settings TEXT                   -- 其他可配置项收口
);
```

### 3.2 分类体系（自定义）
- 标准 5 类作默认模板：`IP知识类 / 建筑工程类 / 税务合规类 / 工商代理类 / 资质代办类`。
- 旧 2 类（财税知识类/营销类）映射迁移：财税知识类→税务合规类+IP知识类；营销类→IP知识类。
- 租户可在后台**增删改/排序/启停**分类；前端所有"视频类别"下拉均读 `category_schema`，支持自定义创建编辑选择（满足"各模块分类字段支持用户自定义"）。
- 项目 meta 改 `categories:[]` 多标签；`/api/projects?category=` 支持检索。

## 4. 细粒度权限控制模块

### 4.1 权限模板
```sql
CREATE TABLE permission_templates (
  id TEXT PRIMARY KEY,
  tenant_id TEXT,                 -- NULL=系统内置模板，可复用
  name TEXT,
  module_switches TEXT,           -- JSON: {"创作台":true,"批量生成":false,"多账号分发":true,...}
  data_scope TEXT,                -- JSON: {"categories":["税务合规类"],"date_range":"all"}
  rate_limits TEXT,               -- JSON: {"api_per_min":60,"video_per_day":50}
  billing_mode TEXT,              -- metered / subscription
  thresholds TEXT,                -- JSON: {"video_month":1000,"alert_at":0.8}
  inherit_from TEXT               -- 可继承另一模板
);
CREATE TABLE tenant_permissions (
  tenant_id TEXT PRIMARY KEY,
  template_id TEXT,
  overrides TEXT                  -- JSON: 在模板基础上按需自定义的项
);
```

### 4.2 实时生效
- 每次 API 请求经权限中间件：读 `tenant_permissions` → 校验模块开关/数据范围/频率。
- 管理员改模板/覆盖项 → **立刻**对新请求生效，无需用户重新登录（满足要求）。
- 模板可复用（系统内置几套：基础版/专业版/企业版）+ 按需自定义。

## 5. 计费与阈值模块

```sql
CREATE TABLE usage_records (
  tenant_id TEXT, metric TEXT,    -- videos / minutes / api_calls
  period TEXT, value INTEGER, updated_at INTEGER
);
CREATE TABLE billing_events (
  tenant_id TEXT, type TEXT,      -- alert / limit / charge
  metric TEXT, threshold REAL, triggered_at INTEGER, handled INTEGER
);
```
- **两种模式**：`metered`（按量，如出片分钟数×单价）、`subscription`（定期，如月费包额度）。
- 计量中间件累加 `usage_records`；达到 `thresholds.alert_at`（如 80%）→ 触发**充值提醒**（站内信/邮件）；达到 100% → 按配置**功能降级/限制**（如暂停批量生成，保留核心独白出片）。
- 阈值与计费模式均可在权限模板/租户配置中配。

## 6. 管理后台模块（四大子模块）

前端独立 `管理后台` 分区（仅 `role=admin` 可见）：

1. **租户列表**：表格展示租户（状态徽标 active/suspended/expired、用量进度条、套餐、到期日）；支持筛选/排序/查看配置详情/启停。
2. **权限模板配置**：模板 CRUD + 继承 + 模块开关矩阵 + 频率/数据范围/计费模式/阈值可视化编辑；一键套用到租户。
3. **操作日志审计**：`audit_logs` 表记录所有关键操作（登录/创建/修改/删除/计费变更/设备绑定）；支持按**时间范围 / 租户 / 操作类型 / 操作人**多维筛选 + 导出 CSV。
4. **设备绑定管理**：设备列表（在线/离线状态、是否主控制台、最后心跳）；批准新设备/解绑/设为主控。

```sql
CREATE TABLE audit_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id TEXT, actor TEXT, action TEXT, target TEXT,
  detail TEXT, ip TEXT, created_at INTEGER
);
```

## 7. 数字人核心功能（无限克隆 + 分类自定义）

- **模特注册表** `models_registry`：`file → {display_name, role, scene, tenant, source, tags}`。
  - 命名规范：`{品牌}_{角色}_{场景}_{版本}`（如 `HGTT_zhanglao_taxlecture_v1`）。
  - 对外显示专业名（"张老师·财税主讲"），内部仍用文件 id 出片。
- **无限次克隆/重克隆/删除/使用**：上传静音驱动视频 → 注册 → 出片使用；可删除重传、重新克隆（本地零边际成本，是相对头部的真优势）；操作全程从客户视角设计（引导式上传、预览、风险提示），不机械限制。
- **场景/声音**：场景（背景）库按租户管理，支持上传/删除/标签；声音（CosyVoice 克隆音）同理无限次。
- **分类自定义**：见 §3.2，所有内容分类字段均用户自定义。

- **身份验证**：租户 token + 设备指纹双因子（§2.3）；控制台访问强制鉴权。

## 11. 关键风险与避坑（来自本project错题本 L3-3）

- Python 改动必须 `py_compile` 真实文件 → 管理员 `Restart-Service HGTStudio` → 脚本真打接口断言生效，缺一不可。
- 字符串拼接提示词/SQL 易 SyntaxError，改动后用脚本精确替换并立即编译。
- 多租户改造不得破坏现有单租户创作链路（先兼容 default 租户）。
