# 后端多租户存储设计草案（Workspace / Tenant Storage）

> 文档定位：为「数字人自动发布平台」走向商用 SaaS 而写的多租户存储底层规范。
> 阅读对象：后续接手开发的工程师，或老板据此验收。
> 配套文档：`后端商用化重构规划.md`、`架构缺陷大白话分析与商业化路径.md`
> 约束前提：本平台当前单机运行（RTX 5060 8GB 显存）、本地磁盘存储、尚无鉴权与数据库。本草案只解决**存储与隔离**，鉴权/计费另文。

---

## 一、目标与范围

**要解决什么**
1. 每个租户（工作空间）的视频、音频、文稿、素材**物理隔离**，互不串门。
2. 文件命名有章法，便于排查、迁移、审计。
3. 所有数据查询**强制带租户条件**，从机制上杜绝越权。
4. 本地磁盘 → 云端对象存储的切换**业务代码零改动**。

**不解决什么（另文负责）**
- 注册/登录/鉴权（JWT、密码哈希）——见后端规划阶段二
- 计费引擎（时长/分辨率/并发）——见后端规划阶段三
- 视频渲染、队列调度本身——现有 8385 已具备异步队列

---

## 二、核心概念：工作空间（Workspace）

工作空间 = 一个租户的独立隔间，包含其**全部家当**：账号、数字人形象、文稿、成片、素材、配额、账单。

| 字段 | 说明 | 是否可重名 |
|---|---|---|
| `workspace_id` | 系统发的"身份证号"，全局唯一，如 `ws_8f3a2b91c4e2` | ❌ 永不重复 |
| `display_name` | 贴在门上的标签，如"张老师的财税号" | ✅ 允许重名 |
| `owner_user_id` | 创建者账号 | — |
| `plan` | 套餐等级（standard / pro / enterprise） | — |
| `created_at` | 创建时间 | — |

> **大白话**：100 个租户都叫"财税工作室"没关系，系统靠那串身份证号把他们分得清清楚楚，文件各进各的抽屉。

## 三、ID 生成方式

| 对象 | 格式 | 生成时机 | 示例 |
|---|---|---|---|
| workspace_id | `ws_` + UUID4 去横杠前 12 位 | 注册工作空间时 | `ws_8f3a2b91c4e2` |
| user_id | `u_` + UUID4 去横杠前 12 位 | 注册账号时 | `u_a1b2c3d4e5f6` |
| 文件实例 id | UUID4 完整（用于文件名防冲突） | 每次保存文件时 | `a1b2c3d4-...` |

**为什么不用自增数字（1、2、3）**：自增会暴露"你有几位客户"（竞品可枚举），UUID 不可猜、不可枚举，安全性更好。

**生成代码示例（伪代码）**
```python
import uuid

def gen_workspace_id() -> str:
    return "ws_" + uuid.uuid4().hex[:12]   # 48bit，碰撞概率可忽略

def gen_user_id() -> str:
    return "u_" + uuid.uuid4().hex[:12]
```

## 四、存储路径规则

### 4.1 本地阶段（当前 / 内部试用）
根目录由配置 `STORAGE_ROOT` 决定（现 `output/`）。结构：

```
{STORAGE_ROOT}/
└── ws_{workspace_id}/
    ├── audio/          # TTS 音频
    ├── video/          # 成片 mp4
    ├── pkg/            # 字幕/文案/包装产物
    ├── avatar/         # 数字人形象静默视频壳
    └── asset/          # 用户上传的素材（背景/BGM/Logo）
```

**文件命名规范**
```
{类型目录}/{yyyy}/{mm}/{dd}/{file_uuid}_{safe_name}.{ext}
```
例：
```
output/ws_8f3a2b91c4e2/video/2026/07/30/a1b2c3d4-...._公转私解读.mp4
```
- `file_uuid` 防同日同名校冲突
- `safe_name` 取自用户原文件名，过滤掉中文以外可能造成路径遍历的字符（`../`、空格转下划线）

### 4.2 云端阶段（对外租用，对象存储 OSS/S3/COS）
单一 Bucket，用 **Key 前缀**做隔离（不用每租户一个 Bucket，管理成本更低）：

```
bucket: hgt-video-prod
key:  ws_{workspace_id}/video/2026/07/30/{file_uuid}.mp4
```

**为什么不按租户分 Bucket**：租户量上来后 Bucket 有配额上限（如单账号 100 个），前缀方案无限扩展。若需更强隔离，可用对象存储的「前缀级 IAM 策略」限制某密钥只能访问特定 `ws_` 前缀。

## 五、隔离查询必带条件（红线）

多租户系统 90% 的安全事故来自"漏写租户条件导致 A 看到 B 的数据"。本草案用**三重保险**杜绝：

**1. 数据库查询必带**
```sql
-- 正确
SELECT * FROM videos WHERE workspace_id = :ws_id AND id = :vid;
-- 错误（缺 workspace_id → 越权）
SELECT * FROM videos WHERE id = :vid;
```

**2. 文件操作路径必带 ws_id 前缀**
任何 `open / save / delete` 拼路径时，前缀必须是 `ws_{workspace_id}/`，且校验最终路径不包含 `..` 跳出该前缀。

**3. 中间件自动注入，防手滑**
在请求入口（鉴权中间件）解析出 `workspace_id`，存入请求上下文（如 `request.ws_id`），所有 Repository 方法**强制要求传入 ws_id 或从上下文取**，不传就报错。这样漏写会在开发期直接抛异常，而非上线后泄露。

> **P0 红线**：任何新增接口，若代码评审发现查询/文件操作未带 `workspace_id`，一律打回，不准合并。

## 六、Storage 抽象接口（平滑迁移关键）

业务代码**永远不直接读磁盘**，只调接口。今天落本地、明天落云端，业务零改。

```python
# storage/abc.py
from abc import ABC, abstractmethod

class Storage(ABC):
    @abstractmethod
    def save(self, ws_id: str, rel_path: str, data: bytes) -> str:
        """保存，返回可访问的 key 或 url"""
    @abstractmethod
    def get_url(self, ws_id: str, rel_path: str, expire_sec: int = 3600) -> str:
        """返回临时访问地址（本地返回 /static/...，云端返回带签名 URL）"""
    @abstractmethod
    def delete(self, ws_id: str, rel_path: str) -> None: ...
    @abstractmethod
    def list(self, ws_id: str, prefix: str) -> list[str]: ...

# storage/local.py  —— 当前用这个
# storage/oss.py    —— 上云用这个（实现同样接口）
```

切换只需改配置 `STORAGE_BACKEND=local|oss`，无需动业务代码。

## 七、本地 → 云端迁移路径（四步）

| 步骤 | 动作 | 风险 | 灰度 |
|---|---|---|---|
| 1. 抽象接口 | 抽出 `Storage` 接口，本地实现先上 | 低 | 全量 |
| 2. 双写期 | 同时写本地 + 云端，读仍走本地 | 中（一致性） | 10% 流量 |
| 3. 切读 | 读切云端，本地保留做回滚 | 中 | 50% → 100% |
| 4. 搬运 + 停本地 | 后台批量搬历史文件，停双写 | 低 | 全量 |

**关键**：第 1 步现在就该做（零成本），别等上云前才重构。

## 八、重名与冲突处理汇总

| 冲突点 | 解法 |
|---|---|
| 工作空间显示名重名 | 允许，物理隔离靠 `workspace_id` |
| 同租户同日同文件名 | 文件名带 `file_uuid` 前缀 |
| 路径遍历攻击（`../../`） | 保存前校验最终路径仍位于 `ws_{id}/` 前缀内 |
| 云上 Key 冲突 | `ws_id` + `file_uuid` 双重唯一 |

## 九、与现有系统的衔接

- **现有 8385**：`output/audio`、`output/video`、`output/pkg` 现混放、无 ws_id。迁移时写脚本把存量文件按"归属账号"搬进 `ws_{id}/` 目录，并在 DB 建 `videos` 表补 `workspace_id` 列。
- **现有异步队列**：`QUEUE` 每个任务已可带用户标识，补 `workspace_id` 即可实现"成片只进该租户目录"。
- **HEYGEM 看门狗 / 队列监控**：不变，仍负责渲染稳定性，与存储隔离正交。
