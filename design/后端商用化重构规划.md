# 后端商用化重构技术规划（内部试用 → 对外营销租用）

> 配套前端原型：`ui_design/studio_prototype.html`
> 本文承接《平台技术审查与SaaS可行性评估》《架构缺陷大白话分析与商业化路径》的结论，把后端重构成一条可落地的商用路径。

## 〇、现状事实（基于真实代码核查，不是空想）

| 项 | 现状 | 对商用的意义 |
|---|---|---|
| 在线后端 | `gpt_sovits/rewrite_studio.py`（2072 行，纯 `http.server` 单体，**零鉴权**） | 内部够用，对外开放前必须加门禁 |
| 异步队列 | **已实现**：`QUEUE`/`queue_worker` 守护线程（严格串行）+ `GET/POST/DELETE /api/queue` | 路线 A 地基已具备，不用重造 |
| 多租户 | 无；`szrstudio/` 里有 `saas_plan.html`（`tenant_id` 隔离雏形）但没接上 | 对外前的硬缺口 |
| 存储 | 本地 `output/` 磁盘，无对象存储 | 后期须抽象 `Storage` 接口接云 |
| 双后端 | 线上标准库单体 + `szrstudio/` FastAPI 草案并存 | **必须先统一技术栈**，否则越改越乱 |
| 并发 | 单 HEYGEM、8GB 显存（RTX 5060），本地多开不可行 | 内部用异步队列；弹性靠云 GPU |

**核心判断**：方向（财税垂直 + 数字人双声 + 自动出片）有真实价值，已跑通；SaaS 技术上完全可行，但必须先铺四块地基——**统一技术栈 / 加鉴权 / 上数据库 / 上队列与存储抽象**，别在 2072 行单体上硬打多租户补丁。

## 一、商用路径与后端对应关系

### 阶段一：内部闭环试用（MVP，现在～1 个月）
**目标**：稳定生产、收集反馈，不做任何对外入口。
- 保留 `rewrite_studio.py` 生产，但**把队列能力正式启用**（前端接"加入批量队列 + 显示排队位 + 完成通知"，参考已交付的 `queue_monitor.py` 思路）。
- **必做零成本项**：
  1. 给 8385 加一层最简 Token 鉴权（局域网内防误触/防泄露）；
  2. 修 `subprocess.Popen` 命令拼接（注入风险，SaaS 化前必须）；
  3. HEYGEM 自愈看门狗（已交付 `heygem_watchdog.py`，2 分钟内自动复活）。
- 数据：仍用本地文件/SQLite 即可，不引多租户。

### 阶段二：内测成熟后对外营销（1～3 个月）
**目标**：营销官网 + 邀请制注册 + 控制并发成本。
- **统一技术栈**：将核心能力迁到 FastAPI（灭掉双后端），结构 = 路由层 / 服务层 / 队列层 / 存储层。
- **加鉴权**：JWT + 登录，区分内部/admin/租户用户。
- **多租户隔离**：所有资源（项目、脚本、成片、音色、额度）带 `workspace_id`；`szrstudio/saas_plan.html` 的 `tenant_id` 思路直接落地。
- **用量计费引擎（先记账不收费）**：每次渲染记录 `workspace_id / 时长 / 分辨率 / 消耗额度`，前端"生成额度"进度条即来自此。
- **对外入口**：独立营销落地页（展示亮点/案例/定价），不走生产工作台。

### 阶段三：正式商用租赁（3～6 个月+）
- **计费上线**：套餐分级（内部试用 / 专业版 / 企业版）+ 按量（分钟·分辨率·并发）。
- **对象存储 + CDN**：成片从本地磁盘迁对象存储（见阶段三方案），前端播放走 CDN。
- **Webhook 通知**：任务完成、欠费、套餐到期回调客户系统。
- **API 开放**：供财税同行把脚本批量灌进来自动出片（原型 `API 文档` 页已占位）。
- **弹性渲染**：本地 HEYGEM 满员时自动开云 GPU 灶台（见《并发出片方案》）。

## 二、关键模块设计

### 1. 多租户（workspace）隔离
```
workspace (租户)
 ├─ users (成员, role: owner/admin/editor/viewer)
 ├─ projects (视频项目, 含 script / avatar_config / status)
 ├─ avatars (数字人, 自有克隆 vs 预设, 按 workspace 可见)
 └─ usage_logs (每次渲染: duration/resolution/cost_minutes)
```
所有查询强制 `WHERE workspace_id = :ws`，中间件从 JWT 解析；预设资源为 `workspace_id = 'public'` 共享。

### 2. 异步任务队列（已有地基，补弹性）
- 复用现有 `QUEUE` + `queue_worker` 串行模型，抽成独立 `QueueService`。
- 任务状态机：`queued → rendering → done / failed`，每个任务带 `workspace_id`（天然实现隔离）。
- 渲染 Worker 池：本地 1 个（本机 8GB 卡）；后期 `CloudGPUWorker` 在队列积压时按需起（Serverless GPU，按秒计费，闲即关）。
- 对外暴露：`POST /v1/videos`（提交）、`GET /v1/videos/:id`（状态）、`Webhook` 完成通知。

### 3. 用量计费引擎
```
计费因子 = f(视频时长, 分辨率, 是否双人对播, 是否克隆音)
额度扣减：渲染开始预扣，失败回退
套餐：专业版含 N 分钟/月，超出按 ¥X/分钟
```
前端"生成额度 12/50 分钟"进度条即此引擎输出；阶段二只展示不扣费，阶段三接支付。

### 4. 存储抽象（平滑上云的关键）
定义接口，业务代码零改动切换：
```python
class Storage:
    def save(path, bytes) -> url
    def get(url) -> bytes
    def delete(url)
# LocalStorage (现状)  →  OssStorage (阿里云OSS/腾讯COS) → CDN 加速
```
**现在就抽象**，后期只换实现类，不返工业务。

### 5. Webhook 通知
- 事件：`video.done` / `video.failed` / `quota.low` / `subscription.expired`
- 校验：签名头 `X-HGT-Signature`（HMAC），防伪造。

## 三、阶段三「本地 → 云端存储」过渡方案（平滑可行）

| 步骤 | 动作 | 成本 | 风险 |
|---|---|---|---|
| 1 | 抽象 `Storage` 接口，本地实现先上 | 0 | 无 |
| 2 | 新成片双写（本地+对象存储）一段时间 | 低 | 无（可回退） |
| 3 | 读路径切到对象存储+CDN，旧本地保留备份 | 存储按 GB、流量按 GB | 低 |
| 4 | 清理本地旧文件，全量上云 | 同上 | 需备份校验 |

结论：**过渡平滑**，前提是步骤 1 现在就做。一次性后期搬运成本高、易返工。

## 六、风险红线（Review 必查）
1. 无鉴权不得对外开放（商业机密 + 算力被白嫖）。
2. 命令拼接注入点未修前不得上云（云上暴露面更大）。
3. 多租户 `workspace_id` 过滤缺失 = 串户事故，每个查询必须带。
4. 计费预扣/回退逻辑必须幂等，避免多扣或漏扣。
